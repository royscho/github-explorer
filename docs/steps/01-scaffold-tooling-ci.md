# Step 01 — Scaffold + tooling + CI

## Goal

Bootstrap the React Native CLI app (New Architecture on) that every later milestone builds on, and wire up the
quality gates the project rules require before any feature code lands: TypeScript strict mode, ESLint + Prettier,
Husky + lint-staged, Jest, path aliases, GitHub Actions CI, and the feature-based folder skeleton.

Scope is exactly the milestone 1 row in `docs/DESIGN.md` §16 ("Implementation milestones"): _"RN CLI app, TS
strict, ESLint/Prettier, Husky, Jest, aliases, CI, folder skeleton"_. It also lays the groundwork for:

- §2 (Tech stack) — RN CLI, New Architecture, TypeScript strict.
- §3.2 (Folder structure) — `src/app`, `src/features/*`, `src/shared/*`, path aliases.
- §16 (Code quality, tooling & workflow) — lint/typecheck/test scripts, Husky/lint-staged, CI.

No feature logic, no API calls, no navigation, no native module code — those start in steps 2–7. This step only
needs to produce a project that lints, type-checks and has a passing (near-empty) test suite, on a CI that enforces
the same.

## Files

- `package.json`, `tsconfig.json`, `babel.config.js`, `metro.config.js`, `jest.config.js`, `index.js`,
  `app.json`, `.watchmanconfig`, `Gemfile` (iOS Ruby deps), `.eslintrc`/`eslint.config.mjs`, `.prettierrc.js`
- `android/`, `ios/` (native projects — generated by the template, not hand-written)
- `.gitignore` entries merged with the existing root `.gitignore` (RN adds build artifacts, pods, etc.)

**Create by hand:**

- `src/app/App.tsx` — moved from the template's root `App.tsx`; for now renders a placeholder screen only
  ("GitHub Explorer" text) — no providers/navigation yet (that's step 3).
- `src/app/App.test.tsx` — smoke test.
- `src/features/repos/index.ts`, `src/features/favorites/index.ts`, `src/features/device/index.ts`,
  `src/features/settings/index.ts` — empty barrel files (`export {};`) marking the feature boundaries from
  §3.2; subfolders (`api/`, `hooks/`, `components/`, `screens/`, `store/`) are **not** pre-created — they'll

- `src/shared/index.ts` — empty barrel; `src/shared/constants.ts` — one trivial exported constant
  (`APP_NAME`), used only to prove the `@shared/*` alias resolves at both compile time (`tsc`) and test time
  (Jest `moduleNameMapper`).
- `src/shared/constants.test.ts` — asserts the import via the alias works.
- `.husky/pre-commit` — runs `lint-staged`.
- `.lintstagedrc.js` — `*.{ts,tsx}` → eslint --fix + prettier --write.
- `.github/workflows/ci.yml` — `npm ci`, `npm run lint`, `npm run typecheck`, `npm test -- --ci`.

**Change:**

- `README.md` — add setup/run instructions (install, iOS pods, `npm start`, `npm run ios`/`android`) under the
  existing design-doc pointer; keep the existing content.
- `docs/DESIGN.md` — only if the scaffold forces a deviation (see below); none expected.

## Public APIs

Nothing feature-level yet. The only "API" introduced is structural:

- `src/shared/constants.ts`: `export const APP_NAME: string`
- Path aliases available to every file from this step on: `@app/*` → `src/app/*`, `@features/*` →
  `src/features/*`, `@shared/*` → `src/shared/*`.
- npm scripts: `lint`, `typecheck`, `test` (already required by `CLAUDE.md`), plus the standard RN `start`,
  `ios`, `android`.

## Test list

- `App.test.tsx` — renders `<App />` without throwing (smoke test; no RN Testing Library queries yet since
  there's nothing semantic on screen beyond one `Text` node).
- `shared/constants.test.ts` — imports `APP_NAME` via the `@shared/constants` alias and asserts its value,
  proving alias resolution works identically under `tsc` and Jest.

No loading/error/empty-state tests this step — there's no async or stateful logic yet; that coverage starts
in step 2 (API layer) and step 3 (repo list).

## Out of scope

- Any navigation, theming, providers, or screens beyond the placeholder.
- The `DeviceNetwork` native module and its Codegen spec (step 7).
- Running the app on a simulator/emulator as part of the automated check (step 5 only requires lint/typecheck/
  test to pass) — I'll do a manual iOS simulator smoke run since Xcode/CocoaPods are available locally, but
  Android emulator/SDK availability is unverified and not required to land this step.
- `eslint-plugin-boundaries` for enforced feature boundaries — listed as future work in §18.

## Risks / open questions

- **RN version**: latest stable on npm today is `0.88.0` (New Architecture on by default). I'll pin to that
  exact version rather than `latest` so the scaffold is reproducible.
- **Template merge**: `rnc-cli init` refuses to run in a non-empty directory, so I'll scaffold into a scratch
  directory and move the generated files into the repo root, merging `.gitignore` instead of overwriting it,
  and keeping the existing `README.md`/`docs/`/`.claude/`/`.github/pull_request_template.md` as-is.
- **Node 25.9.0** is newer than RN's documented support range (RN officially targets Node 18/20 LTS); it will
  likely work but if `npm ci`/Metro misbehave I'll note it as a deviation and pin an `.nvmrc`/`engines` field
  to a supported LTS instead.
- **Android toolchain**: I haven't confirmed an Android SDK is installed locally. Not required for this step's
  checks (lint/typecheck/test are JS-only), but flagging it since `npm run android` may not work here until
  that's set up.
- **ESLint config format**: recent RN templates ship flat-config (`eslint.config.mjs`) rather than `.eslintrc`.
  I'll keep whichever the template generates and add the React Hooks + `no-explicit-any` rules required by
  `CLAUDE.md` on top of it rather than rewriting the format.

## Deviations from DESIGN.md

None anticipated. If the Node version or ESLint config format forces a change, I'll update §2/§16 of

## Follow-ups (from code review)

- Swapped the planned `react-test-renderer` (deprecated under React 19) for `@testing-library/react-native`
  14.x + its `test-renderer` peer, matching DESIGN §2/§15's declared test stack. `App.test.tsx` now renders
  via RNTL and asserts the app name is on screen, instead of only checking that render doesn't throw. Note:
  RNTL 14's `render()` is `async` — tests must `await` it before querying `screen`.
  `@testing-library/react-native`'s jest matchers (`toBeOnTheScreen`, etc.) need no extra Jest setup.
- Added `.eslintrc.js` `ignorePatterns` for `coverage/`, `vendor/`, `ios/`, `android/` so a local
  `npm test -- --coverage` run doesn't leave generated files that fail the next `npm run lint`.
- `App.tsx` imports `APP_NAME` from `@shared/constants` instead of duplicating the string, and `index.js`
  imports `App` via the `@app/App` alias — both now exercise the alias through the real Metro/Babel path,
  not just `tsc`/Jest.
- Widened `.lintstagedrc.js` to also format staged `.js`/`.json`/`.md`/`.yml` files, not just `.ts`/`.tsx`.
- Added `.nvmrc` (`22`) and pointed CI's `setup-node` at it via `node-version-file`, so local and CI Node
  versions can't drift apart.
- Added `permissions: contents: read` and a `concurrency` group (cancel stale runs) to the CI workflow.
- Renamed the npm package from the reverse-DNS bundle id to `github-explorer` (native bundle/package IDs are
  unaffected — those live in `app.json`/`android`/`ios`, set separately).
